# Affordable Housing Nonprofit — Back Office Is Everything Interactive Graphic

## Reframed premise

"Back office" is not a department. It is **everything it takes to run the business** after the mission-facing work is done. For an affordable housing nonprofit, the back office is the full operating system:

- Governance, finance, accounting, audit, HR, payroll, benefits, insurance
- Grants management, compliance, funder reporting, HUD/CAPER/9902/LIHTC
- Fundraising, donor stewardship, marketing, communications, events
- Property portfolio, facilities, maintenance, vendor relationships
- Construction, development, procurement, legal, risk management
- IT, security, identity, devices, email, data protection, AI governance
- Board management, strategic planning, budget, cash flow, banking
- Human resources: hiring, onboarding, reviews, training, time off, policies

The interactive graphic must show that Max Power Suite is not a set of siloed apps. It is the **connected operating system for the entire business** — every workflow, every record, every report, every compliance obligation, every dollar, every person.

## The shared nervous system: every back-office function needs the same things

No matter which business function you look at, the back office is asking the same questions:

1. **Who is this?** — identity, contact, role, permissions, history
2. **What happened?** — records, activities, documents, communications
3. **Is it approved?** — workflows, signatures, committees, authorization limits
4. **How do we pay for it?** — budget, funding source, grant, program, cost allocation
5. **Is it compliant?** — rules, deadlines, reports, documentation, audit trail
6. **Where is the money?** — cash flow, AP, AR, payroll, grants receivable, investments
7. **What do we tell the board and funders?** — dashboards, packets, KPIs, outcome reports
8. **Who is doing the work?** — staff, contractors, volunteers, vendors, capacity
9. **Is our data safe?** — security, privacy, backups, access, AI governance
10. **Are we improving?** — outcomes, metrics, feedback, evaluation, learning

Max Power Suite is designed so every function answers these questions from the same data, the same platform, the same security model, and the same AI layer.

## Interactive graphic concepts

### Concept A: The nonprofit as an operating system

A diagram of a computer motherboard or a city grid. Each "business function" is a district or chip. Data flows between them like power lines or roads. The central hub is the shared Dataverse: one identity, one contact, one property, one funding source, one chart of accounts.

- **Visual:** district blocks for each business function; animated lines showing data flows; a central "Dataverse" power station.
- **Interaction:** hover a district → see its primary activities, the module that handles them, and the data it shares with others. Click a district → go to the module detail page.
- **Toggle:** show/hide the Managed M365 foundation layer (security, identity, email, AI), and show/hide the compliance/audit layer.

### Concept B: "What does it take to run this place?" scroll

A vertical scroll graphic where each section is a day or a week in the life of the organization. The user sees the outside work (classes, closings, construction, rent collection) and the avalanche of back-office work each creates. Then Max Power Suite appears as the system that catches the avalanche and sorts it into the right module.

- **Visual:** split-screen — outside work on the left, back-office workload on the right.
- **Animation:** as the user scrolls, documents, approvals, reports, and payments fly from the left to the right and organize themselves into modules.
- **Last frame:** a clean dashboard with every deadline, report, and dollar accounted for.

### Concept C: The "one record, many lives" network

Start with a single contact (a person) and a single property. Show how the same record is reused across every business function. Maria is a counseling client, a DPA applicant, a donor, a volunteer, a tenant, and eventually a homeowner. The property is a development site, a rehab project, a DPA purchase, and a managed rental unit.

- **Visual:** a network graph with people and property nodes in the center, business functions orbiting around.
- **Interaction:** click a person or property → see every business function they touch, and every module that handles it.
- **Promise:** no duplicate contact records, no duplicate property files, no re-keying between systems.

### Concept D: The board / audit / funder question generator

A tri-fold graphic: three audiences (Board, Auditor, Funder) each asking the same 10 questions. Show how Max Power Suite answers each question from the same data.

| Question | Board asks | Auditor asks | Funder asks |
|---|---|---|---|
| Who did we serve? | Demographics, outcomes, pipeline | Eligibility, documentation, consent | Numbers, demographics, success rates |
| How did the money flow? | Budget vs actual, cash flow | GL detail, support, audit trail | Allowable costs, drawdowns, cost allocation |
| Are we compliant? | Risk register, policy adherence | Controls, documentation, testing | Report deadlines, outcomes, monitoring visit |
| What's the pipeline? | Programs, capacity, impact | N/A | Future funding, sustainability |
| Are properties performing? | Occupancy, rent roll, maintenance | Asset records, reserves | Program compliance, LIHTC |

- **Interaction:** click a question → see the modules and reports that answer it.
- **Best for:** Executive directors and finance directors who have to answer these questions monthly.

### Concept E: "Before / After" operating system stack

Two side-by-side diagrams: the current-state nonprofit stack and the Max Power Suite stack.

**Current state:**
- QuickBooks for accounting
- Excel for everything else
- Google Drive / Dropbox for files
- Mailchimp for email
- Constant Contact for events
- A donor CRM
- A property management system (or none)
- A grant tracker spreadsheet
- A paper file for counseling files
- A different paper file for DPA
- Construction managed by email and spreadsheets
- Vendor bills approved by email chains
- IT handled by whoever is youngest

**Max Power Suite state:**
- One Dataverse for all records
- One security model for all access
- One set of modules for every business function
- Managed M365 for identity, security, email, and AI
- Copilot Studio agents across the data
- QuickBooks/Intacct/MIP for GL, fed by the suite
- Power BI for board and funder reporting

- **Interaction:** hover any current-state tool → see the Max Power replacement and the data flow it enables.
- **Best for:** prospects who already know the pain of their current stack.

### Concept F: "The compliance clock"

A 12-month clock showing every major compliance and reporting deadline an affordable housing nonprofit faces: 9902, CAPER, LIHTC, SHIP, HOME, CDBG, NSP, audit, 990, grant reports, board meetings, recertifications. Show which module produces each output and when it starts warning you.

- **Visual:** circular calendar with color-coded deadlines.
- **Interaction:** click a deadline → see the workflow, the data source, and the module.
- **Toggle:** show deadlines by role (ED, Finance, Compliance, Program Director, Property Manager).

## Copy principles for the full-business graphic

- **Use business language, not product language.** "Loan servicing" and "grant drawdown" are more powerful than "DPA module" and "Grant Management."
- **Lead with the function, then the module.** "Accounts Payable is how every vendor gets paid" is better than "Accounts Payable reads invoices with AI."
- **Show duplication as the enemy.** The current state is not "bad software"; it is the same person entered in 6 systems.
- **Quantify the business risk.** "Missed HUD report = funding pause." "Duplicate property file = wrong lien." "Manual AP = late payments and vendor disputes."
- **Name the audiences.** Board, auditor, funder, program director, finance director, property manager — each sees the same data but asks different questions.

## Technical implementation notes

- Build as a Power Pages web template with inline SVG and vanilla JS.
- Use the same module metadata from `scripts/Build-Site.ps1` so the page stays current.
- Keep animations CSS-driven; avoid heavy JS libraries.
- Ensure accessibility: keyboard navigation, ARIA labels, focus indicators.
- Make the page deep-linkable: `/how-we-run/#operating-system`, `/how-we-run/#stack-comparison`, `/how-we-run/#compliance-clock`.
